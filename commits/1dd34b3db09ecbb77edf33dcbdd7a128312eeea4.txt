ticket 100: what building the screen found, and the one thing still in the way
The module is on wip/ticket-100-port-screen rather than main, because it does not
draw yet and main is not a place to leave a red gate. Its memory is right -- the
backdrop matches the ROM, the palette matches the options screen's C-RAM exactly,
the font, title cells and rows are all where they belong, and the cycle over
$00D5A4/$00D5A6 runs without eating the stack.

Four findings, each cheaper written than rediscovered: a VDP command is one long
write and two word writes pair the commands one word off (which turns the display
off and looks like a broken copy); registers set before the copies undo the copies;
RunTitleScreen leaves its FrameHandler running and it overwrites V-RAM $0000 every
VBlank, which is exactly why the game's screens clear it before loading anything;
and register 4 has to be rearmed every frame after the wait, because the guest
restores it and $00D5A6 is the only point where the port's value survives to the
renderer.

What is left is named as the next task rather than worked around: the renderer takes
the plane layout from reg[16] & 3, the title screen leaves it at $03 where the
options screen has $01, and register 16 is not addressable by a register-write
command at all -- four bits for the number. Nothing in the port assigns it, so the
question is how the guest does.
