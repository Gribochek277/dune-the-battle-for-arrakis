windows: the checks find the port's binaries by their names, and the shared heads by a path the harness reads
Two more of the gate's Windows differences, both in the host shim:

* tests/lib/python/sitecustomize.py: the scripts ask whether
  `port/build/headless` exists before they run it; on Windows the file is
  `headless.exe`, which MSYS2's programs and Windows' process creation both
  find by the short name but Python's existence checks did not. os.stat,
  os.path.exists, os.path.isfile and os.access look at NAME.exe for a
  suffix-less NAME that is not there (scripts/compare_port_state.py was the
  first to say "does not exist").
* tests/lib/gate_shared.sh: the cache's heads are written through
  `--state-save FRAME:PATH`, an argument MSYS2 does not rewrite, so the cache
  directory is spelled the native way when cygpath is there.
