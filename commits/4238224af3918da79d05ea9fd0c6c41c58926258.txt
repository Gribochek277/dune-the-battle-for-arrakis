driver bus: a clock that goes backwards wakes the model too
When the machine's clock goes back (a reset), the model already restarted its
own clock from it, but kept the wake it had computed on the old one, so it would
not have simulated again until the new clock caught up with the old wake. It
is now reset with the clock. The playtest route never takes this branch.

D150's description of where the stand-in is consulted says "the 68000's
instruction boundaries" rather than "after every instruction", which the
machine no longer does.
