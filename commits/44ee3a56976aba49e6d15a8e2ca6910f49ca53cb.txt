198: the player's save is the cartridge's battery window
The cartridge declares 32 KiB of battery RAM at $00200000-$0020FFFF and its
code never touches it: scripts/scan_sram.py finds 3 204 four-byte values inside
the window and none is an instruction's operand, and the playtest route's
10 400 frames make 0 accesses now that the bus counts them. The game's progress
travels through the password screen, a 14-entry level-select table, and the
title screen has no save row. So the port declares the save's layout in the
window the header names, keeps the window mapped (the memory map's twelfth
region), and makes the save that image:

* next/save_state.{c,h}: the game's state as eight regions of work RAM -- the
  record world, the map, the mission's block and its slices, the view, the
  random seed -- with a header (magic, schema version, the identity: frame,
  side, mission, level, the live record counts) and a CRC-32, compressed with
  an RLE stream into the 32 KiB (the raw state is 52 761 bytes; the committed
  mission's payload is 14 536). The identity's counts are the state layer's
  (GUEST_RECORD_ALLOCATED), and the mission clock it uses to answer "is the
  mission running" is a new state-layer accessor (guest_mission_clock).
* app/save_file.{c,h}: the container -- savegame.dsv beside the binary,
  "DUNESAVE", version 1, the 32 KiB image and a SHA-256; a version-0 file (the
  image alone, an emulator's .srm) is read and reported as raw.
* app/play_save.{c,h}: F7 writes, F8 loads, --load-save waits for the mission
  it names (side, number, clock and a live force), a load clears the port's own
  selection; the window's imperative half, so run_play.c stays under the zone
  bound (it was over; the port's feature report lines moved to play_report.c).

The harness has --save-at FRAME:PATH, --load-save PATH, --load-at FRAME and
--perturb-save (the check's control), and prints the window's access count and
whether the battery holds a save. The playtest route declares the save and load
steps in analysis/playtest-route.json's "saves" section (scripts/playtest_route.py
--saves/--check), scripts/playtest.sh gains --save-at STEP and --from-save FILE,
and scripts/scan_sram.py is the static half of the finding.
