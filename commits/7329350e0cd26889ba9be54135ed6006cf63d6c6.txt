ticket 200: the transcriptions' MOVEQ clears V and C, and the fixtures are re-recorded
The first suite run after the corpus left failed `structures: DamageUnit takes a
hit` on the status register. The cause was real and old: the transpiler's MOVEQ
emitter set N and Z and never cleared V and C, which the M68000 PRM requires,
and the port's transcriptions had copied the omission in 1 813 places. The
differential sweep could not see it because it started every instruction from
`sr = $2700`, where both flags are already clear, and `moveq_to_d()` in
`next/records_shared.h` documented the divergence as deliberate conformance to
the corpus -- as did `read_controller.c`, in a comment that named the address
the fuzz would one day catch.

Fixed where it came from: `scripts/transpile68k.py`'s moveq emitter, the corpus
regenerated from it, all 89 transcribed parts regenerated by
`scripts/transcribe_group.py`, the 392 hand-written copies, both `moveq_to_d()`
helpers and the four hand-written dispatches (`frame_clock.c`,
`input_state.c`, `read_controller.c`, `selector_rows.c`). The `leaf_helpers.c`
comment that claimed the interpreter set ADDQ's flags is corrected too: ADDQ to
an address register never touches them.

The state corpus is re-recorded (`scripts/oracle_fixtures.sh`, 419 fixtures,
64 of them changed) because the fixtures had banked the old translation's wrong
SR wherever C or V was set at a MOVEQ: `oracle-run` reported `recorded vs C` and
`recorded vs guest` both `$2705 vs $2704` until they were measured against the
interpreter. The 62 hash rows in `analysis/fixtures/*/manifest.txt` that name
those files are updated from the new ones; the routes' own banked state hashes
did not move.

The access trace gets its pc back as well: `md68k_execute()` advances `cpu->pc`
to `ins->next` before the instruction's body runs, so the RAM trace named the
*next* instruction; the interpreter now publishes its own address for the hooks
(`md68k_executing_pc`, `port/machine/md68k_priv.h`), which is what the
translated path recorded and a 68000 reports.
