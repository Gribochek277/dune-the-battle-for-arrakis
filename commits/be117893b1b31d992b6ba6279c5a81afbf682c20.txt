ticket 99: the title is written while the screen is still dark, so it never flickers
The owner reported OPTIONS appearing and becoming PORT SETTINGS, and read that as
the design showing -- a screen being edited at runtime rather than a screen being
had. On the merits they are still right about what this is. But the flicker itself
was not the architecture: the hook stood at $010974, the last instruction before
the loop, which is *after* the palette fade at $010958 that brings the screen up.
Moved to before the fade, the game's word is in the cells for exactly one frame,
2236, and that frame is black -- zero pixels of 76 800 that are not black -- so the
first frame anyone can see already says PORT SETTINGS.

The test now asserts the property that matters rather than the one that was handy:
across the arrival, no frame that has a pixel which is not black holds the cells
spelling OPTIONS. A plane-only check passes a build that shows the game's title for
a frame; a picture-only check passes a build whose title was never written. Both
are read at every frame of the arrival.

Worth being straight about what this does not settle: the port's screen is still
the game's options screen with the port's words on it, and it still inherits nine
rows it has to suppress. That argument for a screen of the port's own stands on its
own merits -- ticket 100 -- and it is a worse argument than it looked when the
flicker seemed to prove it.
