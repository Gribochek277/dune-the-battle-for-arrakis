compare: port state vs BlastEm reference, with the first divergence
scripts/compare_port_state.py runs port/build/headless (building it when it is
missing), loads the reference capture for the frame the port actually reached
-- capturing it with scripts/capture_state.py when it is absent -- and prints
the verdict: identical, or the first differing address with both values, the
surrounding bytes, the differing registers and the rendezvous of both sides.
It also points at the ROM code that mentions the first differing address and at
the first address the port reached that the reference never did (the two logs
have different block granularities, which the report says).

Exit status: 0 identical, 1 differing (a port that stalls before the requested
frame count counts as differing), 2 when no comparison is possible (no harness,
unusable JSON, no reference and no way to capture one). The reference side
needs the emulator; the port side does not, and the script never writes to the
ROM.

tests/test_headless.sh proves both tools with no display and no emulator: the
harness runs under `env -i`, two runs are byte-identical (state and address
log), the dumped work RAM matches its own sha256, and the comparator reports
identical / differing / missing-reference / wrong-frame correctly. It is part
of tests/run_all.sh now.
